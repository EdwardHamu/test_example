## 1. 探针：更早读取短回答的模型信息

定位：新版 `ArenaModelProbe-09.18.01-x64-extracted/{app}/assets/arena-model-probe.inject.js` 第 2319–2328、2356–2395、3224 行；顶层对应 `pollRunModels`、`startAutoResolve` 和 boot 中的启动参数。

| 行为 | 顶层当前实现 | 09.18.01 原版 |
| --- | --- | --- |
| run-token 后自动采集初始延迟 | 8000ms | 2500ms |
| 尚未读到模型时的轮询间隔 | 默认固定 6000ms | 默认从 1500ms 开始，每次乘 1.6，最高 6000ms：1500 → 2400 → 3840 → 6000… |
| 回答完成后的补采集循环 | 2 次；每次分别等待 2000、6000ms | 3 次；每次分别等待 500、2000、5000ms |
| 已识别模型、继续补全详情时 | 每次默认等待 6000ms | 前两次等待 2000ms，之后使用配置间隔，默认 6000ms |
| initialDelayMs 参数默认值 | `opts.initialDelayMs || 8000` | `opts.initialDelayMs ?? 8000`，可显式传入 0 |

注意：完成后循环的等待是**逐次累加**，不是从完成时刻开始的绝对时间。忽略请求耗时和调度延迟，顶层约在完成后 2、8 秒发起补采集，新版约在 0.5、2.5、7.5 秒；真实请求还受 fetching、fetchCount、token/页面状态和 429 保护限制，不能保证三次都实际发出网络请求。

这些变化尤其适合当前默认提示词“只回答数字1，不要补充其他文字。”这种很快结束的响应。改动主要是采集时序，并非新增模型匹配规则或重写推理识别算法；请求前期更密集，需要继续保留限流和过期会话保护。

新版仍保留普通请求/最终请求计数上限（`opts.final ? 10 : 8`）、HTTP 429 退避及会话代际校验。它并不要求改变用户指定的每轮至少 10 秒抽卡冷却。

## 2. PageBridge：转圈不再直接当作附件错误

定位：新版 `ArenaModelProbe-09.18.01-x64-extracted/{app}/assets/PageBridge.js` 第 95–101 行。

- 顶层当前 gacha 分支把“发现已暂存附件”或“日志外可见进度条/转圈”统一抛出错误。
- 新版区分两者：有已暂存附件继续报错并保留；没有已暂存附件但存在转圈/进度条时，返回 `{waiting:true}`。
- 意图是避免新对话加载、模型路由时的转圈被误认为上传附件，从而不必要地结束抽卡。
- 此变更只在 gacha 分支；新版 testFill/testSend 等入口仍保留原先的严格附件/上传检查，并非所有输入入口都放宽。
- 合并时需要同时考虑本地 `typeDraft` 的检查逻辑。不能只替换独立 PageBridge 文件却忘记探针内嵌副本；应运行 `node sync-page-bridge.cjs` 并复测。
- “没有已暂存附件”不绝对证明未发生上传，应保留真正的附件和发送前检查，不把整个附件保护删掉。

## 3. CandidateBridge：重命名操作兼容性

定位：新版 `ArenaModelProbe-09.18.01-x64-extracted/{app}/assets/CandidateBridge.js` 第 13–26、69、76–81 行。

1. 提取 `renameMenuButton()`：找到当前对话链接后，从其父节点起最多检查 4 层祖先容器，在每层寻找唯一的 More options / 更多选项 / 更多按钮。不再只看直接父节点。
2. 保留 `renameMenu` 的 pointerdown 行为，新增 `renameMenuClick`，使用 `.click()` 打开同一菜单，给宿主提供另一种调用方式；不是自动失败重试两种事件。
3. `state` 返回值新增 `renameSaveReady`，表示检测到了重命名对话框中未禁用的 Rename / 重命名 / 保存按钮。
4. 需要注意的行为变化：顶层要求当前对话链接唯一，新版改为有匹配链接即可取第一个。提高了某些重复 DOM 下的兼容性，但放宽了歧义保护。建议迁移时复核是否应该保留唯一性检查，避免匹配到了错误行。
5. 新接口是否被桌面调用取决于宿主实现；仅看 assets 不能证明 EXE 已如何使用它们。

## 4. welcome.html：文案区别，不是新的运行逻辑

新包说明是“打开 Arena → 注册/登录并等待自动注册 → 开始抽卡 → 选择卡片二次验证”。顶层增加了“若桌面版本支持”的条件，并提示人机验证、草稿、附件、限流及 assets 不升级 EXE。

没有新增可执行逻辑；建议保留顶层兼容说明，而不是用新包简化文案覆盖。

## 整体覆盖会丢失的本地定制

- 网页内独立“目标抽卡”面板，以及模型名包含 astra/fable 的停止规则。
- 默认提示词“只回答数字1，不要补充其他文字。”。
- 逐字符 keydown/keypress/keyup、50–150ms 随机计划间隔和逐次状态复核。
- 抽卡操作权保护、至少 10 秒冷却与桥接未就绪自恢复。
- 探针内置 PageBridge 及协议兼容检查。
- 会话完成通知、1.5 秒较响的完成音、自动 Esc 和设置入口。
- 人机验证窗口检测与去重警告音。
- 额外完成帧识别、诊断回调容错、reasoning-detail 事件/HUD 刷新。
- 更完整的推理配置/内部提示/Token 统计展示及外部详情的清洗和实时作用域校验。

上游探针版本字符串为 `1.0.0+0a1993bf`，顶层为本地版本 `1.2.4+assets-9.17.9`；两套字符串不是可以直接比较大小的统一发布序列，不能据此判定新安装包比本地脚本“旧”。

## 建议与验证边界

优先增量合并探针采集时序和 PageBridge 的等待行为；CandidateBridge 合并时审查链接唯一性；welcome 保留顶层。迁移后要同步内嵌桥接并重新执行相关测试。

本次依据实际文件的 SHA-256、逐行 diff 和完整变更段审阅。没有执行新版网页逻辑、真实抽卡、注册、登录或桌面运行测试；本报告不声称新版与定制版已完成兼容性验证。
