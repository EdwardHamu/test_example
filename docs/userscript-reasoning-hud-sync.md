# 思考检查融合到探针、内部名上传与当前会话查询（2026.09.26.6）

## 本次任务

1. 思考等级检查结果融合到探针浮窗。
2. 上传会话模型时使用检查得到的内部名。
3. 检查并修复进入/切换会话时服务器查询与左侧列表 DOM 改名。

## 实现

### 探针浮窗

在 HUD Shadow DOM 内新增检查结果容器，复用 `tools/userscript-reasoning.js` 的同一套 DOM 渲染：显式档位、内部名/后缀、预算、模式、Token、最新调用标记及字段来源。原工具面板不再另外挂载该明细，仅保留检查按钮/API。

HUD 重绘时移动原有检查 DOM，不重新创建一套状态；保留已展开的来源，并在恢复滚动位置前重新挂载。检查区每秒刷新，账号/页面/轮次保护仍有效。检查区还显示会话模型同步状态、服务器缓存记录或跨域助手错误提示。

### 内部名上传

`reasoningInspector.uploadModel()` 是唯一的模型写入来源。只输出已通过当前账号、URL、run、generation 和轮次校验的检查结果内部名。

不再读取 `conversationModels()` 的显示名/历史名去 POST；不上传 `模型名 · high` 格式，不根据档位造内部名。若未暴露内部名、记录不完整或多调用记录无法唯一归属，则等待，不猜测、不降级成展示名。现有检查器对多调用的轮次级内部名仍保持保守归属规则。

继续使用原固定 session_model 接口、跨域助手和并发/重试/写入确认规则，不改 API 契约。

### 进入与切换会话查询

静态排查确认的旧代码缺口：

- 查询 ID 仅来自侧栏扫描；当前会话不在已挂载侧栏中时不会主动查询。
- 当前路由没有独立刷新路径，已有正缓存 5 分钟或负缓存 1 分钟可导致切换回来时不重新请求。
- 仅处理第一个侧栏实例；移动端/桌面副本并存时可能遗漏。
- 只观察节点/文本，不观察链接 href 复用。

修复：当前路由独立、优先 GET，进入/切换强制重新校验缓存；popstate/hashchange/Navigation API 事件与 1.2 秒轮询配合覆盖 SPA 导航；未挂载侧栏也能获取记录，稍后挂载再回填。所有侧栏实例按自己的会话 UUID 更新，监听 href 变化并保留 React 重绘回填与 404 恢复原名逻辑。标题仅改 textContent，不调用 Arena Rename，不改服务器保存的聊天标题。

给定网页快照的侧栏仍有 `a[data-sidebar="menu-button"][href]` 和直接子节点 `span.body-sm.truncate`，未发现该快照存在主选择器失配；额外兼容直接 `span.truncate`。不能据此断言用户当前浏览器 DOM 必然一致。

### 跨域助手边界

主脚本保持 grant none，不能绕过浏览器 CORS。仍需安装并启用 `session-model-transport.user.js`。未就绪时重复握手并显示诊断，不偷偷使用 page fetch。静态测试不能证明用户实际安装了助手，也不能证明接口在线或目标会话已有记录。

## 用户验收

更新 `user.js`，确认跨域助手已安装启用，刷新 Arena：

- 探针内可见完整检查结果，重绘后展开的来源仍保留。
- 内部名出现后，POST body 的 model 等于该内部名，而不是请求名或标题加档位。
- 进入/切换会话，服务器 GET 对应当前 UUID；有记录时仅将相应左侧标题 DOM 改为服务器模型名。
- 404、助手缺失、接口错误不会伪造名称，检查区可查看诊断。
