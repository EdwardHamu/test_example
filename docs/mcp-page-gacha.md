# 网页内目标模型抽卡

## 方案与使用

用户选择新增网页内独立流程，而非修改桌面 EXE 的原有“开始抽卡”。实现位于 `assets/arena-model-probe.inject.js` 的 gacha-runner 模块，配套修改 `assets/PageBridge.js`。

1. 重启应用或刷新 Arena 页面，使两个新版脚本加载。页面右下角显示“目标抽卡 · astra / fable”。
2. 展开“提示词与说明”修改每轮提示词，默认“你好，请简短介绍一下你自己。”；支持 1–1000 个 Unicode 字符。
3. 完成登录/验证，清理不打算发送的草稿和附件后，点击网页面板“开始”。不自动启动，不与桌面原有抽卡同时运行。
4. 命中后保留会话和正在生成的回答。停止按钮只终止本流程的后续操作，不删除草稿、不主动中断生成。
5. 遇到暂停需手动处理原因，再重新开始；不是从任意部分输入位置自动恢复。完整刷新不会自动恢复抽卡。

程序接口：`window.__MODEL_PROBE__.pageGacha.start(prompt)` / `.stop()` / `.state()`。页面桥接缺失时开始操作明确报错，不回退到无保护发送。需要宿主实际加载更新后的 PageBridge；没有修改 EXE 的加载时机。

## 匹配与流程

- 不区分大小写地匹配模型名是否包含 astra 或 fable；不读取聊天正文中的关键词、不根据模型家族猜测。
- 模型来源是本轮 run trace 已识别的 modelName，绑定 BUS generation、当前会话 URL 及 tokenUrl；启动前旧模型、其他会话模型不计入。
- 新对话 → 就绪确认 → 分段输入 → 发送前复核 → 等待模型名/回答 → 至少 10 秒冷却 → 未命中则下一轮。
- 正常情况下没有固定轮数上限，可能持续消耗账户额度；用户可随时停止。没有模型名不视为“未命中”而盲目重试。
- 网页初始化等阶段约 30 秒超时，输入阶段 180 秒；发送后的等待总计最多 240 秒，完成后仍无模型名最多等待约 120 秒。超时暂停而不是继续消耗额度。

## 操作节奏与保护

- 初始准备等待 800ms、新对话后等待约 1000ms、开始输入前等待 600ms。
- 每次追加 1 个 Unicode 码点（不拆 UTF-16 代理对），每个字符后重新随机选取 50–150ms 的计划等待间隔；输入完成后至少等待 1000ms 再检查发送条件。输入调度每 25ms 检查到期，非输入状态最多每 250ms 检查；实际间隔可能因调度精度或后台节流更长。
- 正常输入事件顺序为 keydown → keypress → 单字符 insertText → keyup；文本由浏览器编辑命令插入，不用 input.value 批量赋值。KeyboardEvent 均为合成事件（isTrusted=false），不伪造可信硬件输入，不模拟完整中文输入法 composition 过程。
- 按键被 preventDefault 时暂停，不强行写入；按键处理后再次检查焦点、页面、草稿和所有权，避免监听器已写入时重复插入。异常时仍通过 finally 派发 keyup。
- 多行提示词使用 Shift+Enter 元数据，避免触发常见的 Enter 发送逻辑；具体网页监听器仍需真实环境验证。
- 沿用原来的 10 秒冷却保护，并在独立流程记录完成时间；实际间隔可能因状态等待和浏览器节流更长。
- 输入前复核草稿前缀、页面 URL、生成状态、附件、弹窗和验证码。发送前重新复核，保留被用户修改的草稿。
- 验证码、登录要求、条款、限流、失败响应、附件及非预期会话变更均会暂停；不自动确认条款、解决验证码或绕过限流。
- 通过 owner 参数隔离带 gacha 标志的 PageBridge 自动操作，暂停/命中时保留所有权以阻止这条入口继续操作；点击停止时释放。无法约束桌面程序绕开桥接的直接导航，不能同时启用两套抽卡。
- 保留现有完成提示音、人机验证警告音、Esc 立即触发。独立面板初始化错误隔离，不导致整个探针启动失败；DOM 尚未就绪时延迟挂载。
